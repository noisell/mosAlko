## О проекте

Я разработал МосАлко для заказчика как MVP интернет-магазина алкогольной продукции. Магазин работает в формате Telegram Mini App: пользователь открывает приложение из Telegram, просматривает каталог, собирает корзину и оформляет заказ в мобильном интерфейсе.

Разработка заняла около **одного месяца**. После завершения я развернул проект в production и передал его заказчику. Позже внес несколько небольших изменений и исправил отдельные ошибки по его запросу. Проект создан для реального использования и получил положительную обратную связь от заказчика.

## Возможности

### Пользовательская часть

- каталог товаров, категории и поиск;
- карточки товаров с изображениями, описаниями, характеристиками и ценами;
- корзина с изменением количества и удалением товаров;
- оформление заказа с адресом доставки, комментарием и промокодом;
- профиль, контактные данные и сохраненные адреса;
- история заказов и повтор заказа;
- мобильная навигация и состояния загрузки для Telegram Mini App;
- локальное сохранение корзины и пользовательского состояния.

### Административная панель

- авторизация администратора и уровни доступа;
- создание и редактирование товаров, категорий, характеристик и изображений;
- просмотр и обработка заказов;
- управление пользователями;
- промокоды и системные параметры магазина;
- статистика по пользователям, заказам и корзинам.

### Telegram-бот

В backend предусмотрен отдельный Telegram-бот для системных уведомлений. Он запускается самостоятельным процессом в Docker Compose и использует тот же backend-контур и конфигурацию окружения, что и API.

## Как устроен проект

Репозиторий разделен на три приложения:

```text
frontend/  пользовательский Telegram Mini App
admin/     панель управления магазином
backend/   API, бизнес-логика, бот и миграции базы данных
```

Пользовательский интерфейс обращается к FastAPI через типизированные API-модули. Backend принимает запрос, передает его в сервисный слой, а тот работает с репозиториями через Unit of Work. Данные хранятся в PostgreSQL. Redis используется для кэширования часто запрашиваемых данных каталога и служебных справочников.

Состояние корзины и пользовательские данные на клиенте разделены по store-модулям Zustand. Это позволяет сохранять быстрые локальные изменения интерфейса и синхронизировать их с сервером при авторизованных операциях.

## Техническая реализация

### Backend

- Python и FastAPI;
- асинхронный доступ к PostgreSQL через SQLAlchemy и asyncpg;
- Pydantic-схемы для валидации входных данных и ответов API;
- предметные модули `auth`, `users`, `products`, `orders` и `admin`;
- Alembic для версионирования схемы базы данных;
- Redis и `fastapi-cache` для кэширования;
- отдельные сервисы и репозитории вместо размещения бизнес-логики в endpoint-функциях.

### Авторизация

Пользователь проходит проверку Telegram WebApp init data. После успешной проверки backend выдает access JWT и refresh-токен в HttpOnly cookie. Административная часть использует отдельный login-flow, refresh-сессию и проверку уровня доступа для защищенных операций.

### Frontend и admin

Обе части написаны на TypeScript, React и Next.js 14. Компоненты организованы по пользовательским разделам: каталог, товар, корзина, профиль, заказы, пользователи, товары, промокоды и статистика. Для стилизации используется Tailwind CSS, для запросов — Axios, для клиентского состояния — Zustand.

### DevOps и деплой

Я подготовил Dockerfile для приложений и Docker Compose-конфигурации для запуска backend, API, Telegram-бота и Redis. Конфигурация и секреты передаются через переменные окружения, а production-значения не хранятся в репозитории. Такой запуск позволяет поднимать сервисы согласованно и отделять код от инфраструктурных настроек.

## Запуск

Для frontend или admin:

```bash
cd frontend # или cd admin
npm ci
npm run dev
```

Production-сборка:

```bash
npm run build
npm start
```

Backend и Redis:

```bash
cd backend
docker compose up --build
```

Перед запуском нужны переменные подключения к PostgreSQL и Redis, а также секреты JWT, Telegram и административной авторизации.
